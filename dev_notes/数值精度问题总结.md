# CUDA → C++ 数值精度移植指南
 
This skill provides systematic guidance for identifying and fixing numerical precision issues
when porting CUDA GPU code to C++ CPU code.
 
---
 
## Core Principle
 
**GPU and CPU floating-point behavior differ fundamentally.** Even identical IEEE 754 operations
can produce different results due to FMA fusion, instruction ordering, compiler flags, and
hardware-specific math libraries.
 
---
 
## Checklist: 移植前必查项
 
When helping a user port CUDA code to C++, systematically check these 9 categories:
 
---
 
### 1. float vs double 默认精度
 
**问题**：CUDA 代码大量使用 `float`（GPU float 比 double 快 2-8x）。移植时不能随意升级为 double。
 
```cuda
// CUDA：float 版本 intrinsic
sqrtf(), sinf(), cosf(), expf(), logf()
```
 
```cpp
// C++ 移植：保持 float，不要换成 double 版本
// ✅ std::sqrtf(), std::sinf() 
// ❌ std::sqrt(), std::sin()  // 改变了精度语义
```
 
**关键判断**：原算法是按 float 精度设计的，升到 double 不是"更准"，而是"行为不同"。
 
---
 
### 2. FMA（融合乘加）
 
**问题**：CUDA GPU 默认开启 FMA（`a*b+c` 是单条指令，无中间舍入）。x86 CPU 默认关闭。
 
```cpp
// ❌ 直接移植：两次舍入，与 GPU 结果不同
float result = a * b + c;
 
// ✅ 显式 FMA，匹配 GPU 行为
#include <cmath>
float result = std::fmaf(a, b, c);   // float
double result = std::fma(a, b, c);   // double
```
 
**影响范围**：迭代算法（神经网络、物理模拟）误差会随迭代指数级放大。
 
编译器开启 FMA 融合：
```bash
g++ -ffp-contract=fast   # 允许编译器自动融合 FMA
```
 
---
 
### 3. 归约求和（Reduction）顺序不确定性
 
**问题**：CUDA warp 归约是树形并行，求和顺序每次可能不同。浮点加法不满足结合律。
 
```cuda
// CUDA warp reduce：顺序不确定
__device__ float warp_reduce_sum(float val) {
    for (int offset = 16; offset > 0; offset >>= 1)
        val += __shfl_down_sync(0xffffffff, val, offset);
    return val;
}
```
 
```cpp
// C++ 顺序求和（结果固定，但与 GPU 数值不匹配）
float sum = 0.0f;
for (int i = 0; i < n; i++) sum += a[i];
 
// ✅ Kahan 补偿求和（更高精度，减小误差累积）
float kahan_sum(const float* a, int n) {
    float sum = 0.0f, c = 0.0f;
    for (int i = 0; i < n; i++) {
        float y = a[i] - c;
        float t = sum + y;
        c = (t - sum) - y;
        sum = t;
    }
    return sum;
}
```
 
**结论**：不追求与 GPU bit-exact 一致时，Kahan 求和精度更高且稳定。
 
---
 
### 4. `__float2int` 浮点转整数
 
**问题**：CUDA 有多种舍入模式转换，C++ 强转永远是截断（向零）。超出范围时 C++ 是 UB。
 
```cuda
__float2int_rn(3.7f)  // → 4  (round to nearest)
__float2int_rz(3.7f)  // → 3  (truncate)
__float2int_rd(3.7f)  // → 3  (floor)
__float2int_ru(3.7f)  // → 4  (ceil)
(int)3.7f             // → 3  (truncate, same as rz)
```
 
```cpp
// ✅ 安全的 C++ 版本（带溢出检查）
#include <cmath>
#include <climits>
 
int safe_float2int_rn(float x) {
    if (!std::isfinite(x) || x > (float)INT_MAX || x < (float)INT_MIN) {
        // 处理溢出：CUDA 返回 INT_MIN/INT_MAX，C++ 是 UB
        return x > 0 ? INT_MAX : INT_MIN;
    }
    return (int)std::roundf(x);
}
```
 
---
 
### 5. FP16（半精度）支持
 
**问题**：CUDA 原生支持 FP16，CPU 无原生 FP16 运算单元（需软件模拟或 AVX-512 F16C）。
 
```
FP16 精度范围：约 3 位十进制精度，最大值 ±65504
FP32 精度范围：约 7 位十进制精度，最大值 ±3.4e38
FP64 精度范围：约 15 位十进制精度
```
 
```cpp
// 方案 1：转 float 计算（精度语义变化，但通常可接受）
float val = __half2float(h_val);
float result = compute(val);
 
// 方案 2：使用 AVX-512 F16C intrinsic（保持 FP16 语义）
#include <immintrin.h>
 
// 方案 3：第三方库 half.hpp
// https://half.sourceforge.net/
#include <half.hpp>
half_float::half a = 3.14f;
```
 
**注意**：FP16 溢出到 65504+ 变成 Inf，这在 CPU float 上不会发生。
 
---
 
### 6. NaN / Inf 特殊值处理
 
**问题**：CUDA 开启 `-use_fast_math` 后，NaN/Inf 行为不符合 IEEE 754。移植到 C++ 后传播路径完全不同。
 
```cuda
// CUDA fast-math 下的危险行为
rsqrtf(0.0f)   // 可能返回 Inf 或垃圾值（非 IEEE）
__logf(0.0f)   // 可能不返回 -Inf
```
 
```cpp
// C++ 默认符合 IEEE 754
#include <cmath>
std::isinf(x)    // 检查 Inf
std::isnan(x)    // 检查 NaN  
std::isfinite(x) // 检查有限数
 
// 防御性检查（原 CUDA 代码用了 fast-math 时必加）
float safe_log(float x) {
    if (x <= 0.0f) return -std::numeric_limits<float>::infinity();
    return std::logf(x);
}
```
 
---
 
### 7. CUDA 数学 Intrinsic 精度（ULP 误差）
 
CUDA 有两套数学函数，精度不同：
 
| 函数 | CUDA `__sinf` (fast) | CUDA `sinf` (accurate) | C++ `sinf` |
|------|---------------------|----------------------|------------|
| 误差 | ~2 ULP | ~1 ULP | 实现定义 |
| `__expf` / `expf` | ~2 ULP | ~1 ULP | 实现定义 |
| `__logf` / `logf` | ~3 ULP | ~1 ULP | 实现定义 |
| `__powf` / `powf` | ~8 ULP | ~2 ULP | 实现定义 |
 
```cuda
// ⚠️ 确认用的是哪套
__sinf(x)  // fast approximate，与 C++ sinf 精度不同
sinf(x)    // accurate，对应 C++ sinf
```
 
**移植规则**：
- CUDA `sinf` → C++ `sinf` ✅
- CUDA `__sinf` → 需要多项式近似或接受精度差异
---
 
### 8. 原子操作精度
 
**问题**：CUDA `atomicAdd` 对 float 的并发结果每次不同。C++ `atomic<float>` 语义不同。
 
```cuda
atomicAdd(&sum, val);  // 并发，顺序不确定，结果每次可能不同
```
 
```cpp
// C++20：atomic<float> 支持 fetch_add
#include <atomic>
std::atomic<float> sum{0.0f};
sum.fetch_add(val, std::memory_order_relaxed);  // C++20
 
// C++17 及以前：用 mutex（顺序确定，但与 CUDA 并行结果数值不同）
std::mutex mtx;
std::lock_guard<std::mutex> lock(mtx);
sum += val;
 
// 或用 double 累加减少精度损失
std::atomic<double> sum_d{0.0};
```
 
---
 
### 9. 编译器优化标志对应关系
 
| CUDA 编译选项 | 含义 | C++ 等价 | 风险 |
|---|---|---|---|
| `-use_fast_math` | 所有近似优化 | `-ffast-math` | ⚠️ 破坏 NaN/Inf 语义 |
| (default) | 精确 IEEE 数学 | (default) | ✅ 安全 |
| `-ftz=true` | 非规格化数→0 | `-ffast-math` 部分 | ⚠️ 影响极小浮点数 |
| `-prec-div=false` | 近似除法 | `-ffast-math` 部分 | ⚠️ 除法精度降低 |
 
```bash
# 推荐：仅开启 FMA 融合，不破坏 NaN/Inf
g++ -ffp-contract=fast -O2
 
# 危险：完全匹配 CUDA fast-math（会破坏 NaN 传播）
g++ -ffast-math -O2
```

## 快速诊断流程
 
当用户报告"移植后数值结果不一致"时，按以下顺序排查：
 
```
1. 检查编译选项
   └─ CUDA 是否开了 -use_fast_math?
      ├─ 是 → 检查 NaN/Inf 路径，考虑加 -ffast-math 或修复代码
      └─ 否 → 继续
 
2. 检查 FMA
   └─ 代码中有 a*b+c 模式的内循环?
      ├─ 是 → 替换为 std::fmaf / std::fma
      └─ 否 → 继续
 
3. 检查归约
   └─ 有并行 reduce/sum?
      ├─ 是 → 顺序求和 or Kahan sum，接受与 GPU 的数值差异
      └─ 否 → 继续
 
4. 检查数学函数
   └─ 使用了 __sinf/__expf/__logf 等双下划线版本?
      ├─ 是 → 这是近似版本，C++ 无直接对应
      └─ 否 → 使用 sinf/expf/logf，对应 C++ 标准库
 
5. 检查 FP16
   └─ 代码中有 __half 类型?
      ├─ 是 → 需要软件模拟或 AVX-512 F16C
      └─ 否 → 继续
 
6. 检查整数转换
   └─ 有 __float2int_r* 系列函数?
      ├─ 是 → 确认舍入模式，用 roundf/floorf/ceilf 对应
      └─ 否 → 继续
```

## 常见代码模式替换速查
 
```cpp
// CUDA → C++ 替换表
__fmaf_rn(a, b, c)     →  std::fmaf(a, b, c)
__fma_rn(a, b, c)      →  std::fma(a, b, c)
__float2int_rn(x)      →  (int)std::roundf(x)   // + 溢出检查
__float2int_rz(x)      →  (int)(x)               // 截断
__float2half(x)        →  需要 half 库
__half2float(x)        →  需要 half 库
__expf(x)              →  std::expf(x)           // 精度略有差异
__logf(x)              →  std::logf(x)           // 精度略有差异
__sinf(x)              →  std::sinf(x)           // ⚠️ __sinf 是近似版
__cosf(x)              →  std::cosf(x)           // ⚠️ __cosf 是近似版
rsqrtf(x)              →  1.0f / std::sqrtf(x)  // 精度不同
atomicAdd(&s, v)       →  s.fetch_add(v) (C++20) or mutex
```

## 验证策略
 
移植后的数值验证建议：
 
```cpp
// 1. 相对误差检查（比绝对误差更合理）
bool check_relative(float gpu_val, float cpu_val, float tol = 1e-5f) {
    float denom = std::max(std::abs(gpu_val), std::abs(cpu_val));
    if (denom < 1e-10f) return std::abs(gpu_val - cpu_val) < 1e-10f;
    return std::abs(gpu_val - cpu_val) / denom < tol;
}
 
// 2. ULP 差异检查（最精确）
int ulp_diff(float a, float b) {
    if (std::isnan(a) || std::isnan(b)) return INT_MAX;
    int ia, ib;
    memcpy(&ia, &a, 4);
    memcpy(&ib, &b, 4);
    return std::abs(ia - ib);
}
 
// 推荐容忍度
// - 一般计算：相对误差 1e-5 (float) / 1e-10 (double)
// - fast-math 移植：相对误差 1e-3 可接受
// - FP16 移植：相对误差 1e-2 可接受
```

# Python → C++ 数值精度移植指南
 
This skill provides systematic guidance for identifying and fixing numerical precision issues
when porting Python algorithm code to C++ CPU code.
 
---
 
## Core Principle
 
**Python 和 C++ 的数值语义有根本性差异。** Python 的 int 无限精度、`/` 永远是浮点除、
负数取模结果为正、`round()` 使用银行家舍入——这些行为在 C++ 中全部不同，且不会有编译错误提示。
 
---
 
## Checklist: 移植前必查项
 
---
 
### 1. 整数除法行为
 
**问题**：Python 的 `/` 永远返回 float，C++ 的 `int/int` 直接截断。
 
```python
5 / 2    # → 2.5  (float)
5 // 2   # → 2    (地板除，向负无穷)
-7 // 2  # → -4   (地板除！)
```
 
```cpp
5 / 2    // → 2   ⚠️ 截断，不是 2.5
-7 / 2   // → -3  ⚠️ 向零截断，不是 -4
 
// ✅ 修复：显式转换
(double)5 / 2       // → 2.5
5.0 / 2             // → 2.5
 
// ✅ 模拟 Python // 地板除（向负无穷）
int py_floordiv(int a, int b) {
    return a / b - (a % b != 0 && (a ^ b) < 0);
}
double py_floordiv_f(double a, double b) {
    return std::floor(a / b);
}
```
 
---
 
### 2. 负数取模（最容易忽视）
 
**问题**：Python 取模结果符号与**除数**一致；C++ 取模结果符号与**被除数**一致。
 
```python
-7 % 3   # → 2   (正数，跟除数符号一致)
7 % -3   # → -2  (负数，跟除数符号一致)
-7 % -3  # → -1
```
 
```cpp
-7 % 3   // → -1  ⚠️ 跟被除数符号一致（C++11起）
7 % -3   // → 1   ⚠️
-7 % -3  // → -1  (这个一样)
 
// ✅ 模拟 Python 取模行为
int py_mod(int a, int b) {
    return ((a % b) + b) % b;
}
// 注意：b 为负时需要额外处理
int py_mod_full(int a, int b) {
    int r = a % b;
    return (r != 0 && (r ^ b) < 0) ? r + b : r;
}
```
 
**高频场景**：哈希表索引、环形缓冲区、角度归一化——这些用到取模的地方都是雷区。
 
---
 
### 3. 大整数 / 整数溢出
 
**问题**：Python `int` 无限精度，自动大数。C++ 整数有固定上限，溢出是 UB（有符号）或回绕（无符号）。
 
```python
2 ** 100          # → 正常工作
factorial(20)     # → 2432902008176640000（正常）
factorial(21)     # → 51090942171709440000（Python 自动升位）
```
 
```cpp
// long long 最大值：约 9.2e18
// factorial(21) = 5.1e19，已溢出！
long long f = 1;
for (int i = 1; i <= 21; i++) f *= i;  // ⚠️ 溢出，UB
 
// ✅ 方案1：__int128（GCC/Clang 扩展，最大 ~1.7e38）
__int128 f = 1;
for (int i = 1; i <= 34; i++) f *= i;  // 支持到 34!
 
// ✅ 方案2：检测溢出
#include <limits>
bool will_overflow_mul(long long a, long long b) {
    return b != 0 && std::abs(a) > LLONG_MAX / std::abs(b);
}
 
// ✅ 方案3：用 double 近似（允许精度损失时）
double f = 1.0;
for (int i = 1; i <= 100; i++) f *= i;  // 精度有损失但不溢出
```
 
**常见溢出场景**：
 
| Python 操作 | 溢出风险 | C++ 安全写法 |
|---|---|---|
| `a * b` 中间结果 | 高 | 转 `long long` 或 `__int128` |
| `n * (n-1) / 2` | 中 | 先除后乘：`(n/2) * (n-1)` |
| `pow(2, 63)` | 高 | `1ULL << 63`（用无符号） |
| 累加循环 | 中 | 监控中间值范围 |
 
---
 
### 4. `round()` 舍入策略
 
**问题**：Python 使用**银行家舍入**（四舍六入五成双），C++ `std::round` 是**四舍五入**（逢五进一）。
 
```python
round(0.5)  # → 0  (五成双，取偶数)
round(1.5)  # → 2
round(2.5)  # → 2  ⚠️ 取偶数！
round(3.5)  # → 4
```
 
```cpp
std::round(0.5f)  // → 1  ⚠️ 逢五进一
std::round(2.5f)  // → 3  ⚠️ 与 Python 不同！
 
// ✅ 模拟 Python 银行家舍入
long long py_round(double x) {
    double f = std::floor(x);
    double diff = x - f;
    if (diff < 0.5) return (long long)f;
    if (diff > 0.5) return (long long)f + 1;
    // diff == 0.5：取最近偶数
    long long fi = (long long)f;
    return (fi % 2 == 0) ? fi : fi + 1;
}
```
 
**影响场景**：统计计算、金融计算、数据预处理中的舍入操作。

### 5. 浮点精度：Python float 默认 64 位
 
**问题**：Python `float` 永远是 64 位 double。C++ `float` 是 32 位，精度损失更大。
 
```python
x = 0.1 + 0.2  # 64 位 double 运算
```
 
```cpp
float x = 0.1f + 0.2f;   // ⚠️ 32 位精度，远比 Python 不准
double x = 0.1 + 0.2;    // ✅ 等价于 Python 的 float
```
 
```cpp
// ✅ 浮点比较永远用 epsilon，不用 ==
bool nearly_equal(double a, double b, double eps = 1e-9) {
    double scale = std::max({std::abs(a), std::abs(b), 1.0});
    return std::abs(a - b) <= eps * scale;
}
 
// 对应 Python 的 math.isclose
bool isclose(double a, double b,
             double rel_tol = 1e-9, double abs_tol = 0.0) {
    return std::abs(a - b) <= std::max(rel_tol * std::max(std::abs(a), std::abs(b)), abs_tol);
}
```

```python
7.0 // 2.0   # → 3.0

```
 
```cpp
// C++ 截断（向零），不是地板除
(int)(-7.0 / 2.0)  // → -3  ⚠️
 
// ✅ 正确模拟
double py_floordiv_f(double a, double b) {
    return std::floor(a / b);
}
```

### 7. `math` 模块函数差异
 
| Python | C++ 等价 | 注意点 |
|---|---|---|
| `math.sqrt(-1)` | `std::sqrt(-1.0)` | Python 抛 `ValueError`，C++ 返回 `nan`，不报错 ⚠️ |
| `math.log(0)` | `std::log(0.0)` | Python 抛异常，C++ 返回 `-inf` ⚠️ |
| `math.pow(x, y)` | `std::pow(x, y)` | 两者都返回 float/double，行为基本一致 |
| `math.gcd(a, b)` | `std::gcd(a, b)` | C++17，需 `<numeric>`，负数处理略有不同 |
| `math.isnan(x)` | `std::isnan(x)` | 需 `<cmath>` |
| `math.inf` | `std::numeric_limits<double>::infinity()` | 或 `INFINITY` 宏 |
| `math.nan` | `std::numeric_limits<double>::quiet_NaN()` | 或 `NAN` 宏 |
| `abs(-3)` | `std::abs(-3)` | ✅ 一致，但 C++ 需要 `<cstdlib>` 或 `<cmath>` |
| `abs(-3.14)` | `std::fabs(-3.14)` 或 `std::abs(-3.14)` | C++ 注意整数 `abs` 和浮点 `fabs` 的区别 |

### 8. 字符串转数字的精度
 
```python
float("1.1")          # 精确解析为最近的 double
int("123456789012345678901234567890")  # 大数，无损
```
 
```cpp
// C++ double 解析：精度基本等价
double x = std::stod("1.1");    // ✅ 等价
 
// 大数：stoll 会溢出！
long long n = std::stoll("123456789012345678901234567890");  // ⚠️ 溢出/异常
 
// ✅ 大数需要用大数库（如 boost::multiprecision）
```

### 9. 列表求和精度（`sum()` vs 循环）
 
```python
sum([0.1] * 10)         # → 0.9999999999999999（有浮点误差）
math.fsum([0.1] * 10)   # → 1.0（精确，Shewchuk 算法）
```
 
```cpp
// C++ 标准库无 fsum，用 Kahan 补偿求和
double kahan_sum(const std::vector<double>& v) {
    double sum = 0.0, c = 0.0;
    for (double x : v) {
        double y = x - c;
        double t = sum + y;
        c = (t - sum) - y;
        sum = t;
    }
    return sum;
}
 
// Python sum() 等价：直接累加（有误差）
double simple_sum = 0.0;
for (double x : v) simple_sum += x;
```

## 快速诊断流程
 
当用户报告"移植后数值结果不一致"时，按以下顺序排查：
 
```
1. 是否有负数参与除法或取模？
   ├─ 是 → 检查 // 和 % 的符号行为差异（最高频错误）
   └─ 否 → 继续
 
2. 是否有大数运算（阶乘、组合数、指数）？
   ├─ 是 → 检查 long long 溢出，考虑 __int128
   └─ 否 → 继续
 
3. 代码中有 round() 吗？
   ├─ 是 → 确认是否需要银行家舍入，替换为 py_round
   └─ 否 → 继续
 
4. C++ 用了 float 还是 double？
   ├─ float → Python 是 double，改为 double
   └─ double → 继续
 
5. 有浮点相等比较（==）吗？
   ├─ 是 → 改为 epsilon 比较
   └─ 否 → 继续
 
6. math.sqrt / math.log 的边界输入？
   ├─ 是 → Python 抛异常，C++ 返回 nan/inf，需添加边界检查
   └─ 否 → 可能是其他问题
```

## 常用模拟函数汇总
 
```cpp
#include <cmath>
#include <climits>
 
// Python 地板除
inline int py_floordiv(int a, int b) {
    return a / b - (a % b != 0 && (a ^ b) < 0);
}
 
// Python 取模
inline int py_mod(int a, int b) {
    int r = a % b;
    return (r != 0 && (r ^ b) < 0) ? r + b : r;
}
 
// Python round()（银行家舍入）
inline long long py_round(double x) {
    double f = std::floor(x);
    double diff = x - f;
    if (diff < 0.5) return (long long)f;
    if (diff > 0.5) return (long long)f + 1;
    long long fi = (long long)f;
    return (fi % 2 == 0) ? fi : fi + 1;
}
 
// Python math.isclose
inline bool py_isclose(double a, double b,
                        double rel_tol = 1e-9, double abs_tol = 0.0) {
    return std::abs(a - b) <=
           std::max(rel_tol * std::max(std::abs(a), std::abs(b)), abs_tol);
}
 
// Python math.fsum（精确求和）
inline double py_fsum(const std::vector<double>& v) {
    double sum = 0.0, c = 0.0;
    for (double x : v) {
        double y = x - c;
        double t = sum + y;
        c = (t - sum) - y;
        sum = t;
    }
    return sum;
}
```

## 总结速查表
 
| 陷阱 | Python 行为 | C++ 差异 | 修复方案 |
|---|---|---|---|
| 整数除法 | `/` 返回 float | `int/int` 截断 | `(double)a / b` |
| 负数取模 | 结果符号同除数 | 结果符号同被除数 | `py_mod(a, b)` |
| 大整数 | 无限精度 | 溢出是 UB | `__int128` 或检测溢出 |
| round | 银行家舍入 | 逢五进一 | `py_round(x)` |
| float 精度 | 默认 64 位 | `float` 是 32 位 | 用 `double` |
| 地板除 | `//` 向负无穷 | `/` 向零截断 | `std::floor(a/b)` |
| sqrt 负数 | 抛 ValueError | 返回 nan | 添加边界检查 |
| log(0) | 抛 ValueError | 返回 -inf | 添加边界检查 |
| sum 精度 | 有误差 | 同样有误差 | Kahan 求和 |
